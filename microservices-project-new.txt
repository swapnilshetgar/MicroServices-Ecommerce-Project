Project Name: CloudCart E-Commerce Microservices Platform
--------

Project Type: Full-stack Kubernetes-based microservices project
-------------

Designed By: Reyaz Sir
------------

CloudCart is a production-style e-commerce platform built using a modern microservices architecture. The project includes a React frontend, API Gateway, multiple Node.js backend microservices, MySQL database, Redis cache, Kubernetes deployment, NGINX Ingress, Prometheus monitoring, and Grafana dashboards.

The frontend provides a real e-commerce user experience with product categories, product cards, search, cart drawer, admin product creation, order placement, reviews, notifications, and project branding. Users can browse products, filter by categories such as Mobiles, Laptops, Electronics, and Accessories, add items to cart, and place orders.

The backend is divided into independent microservices including Auth Service, User Service, Product Service, Inventory Service, Cart Service, Order Service, Payment Service, Shipping Service, Notification Service, and Review Service. The API Gateway receives all frontend API requests under /api and routes them to the correct internal microservice.

MySQL is deployed as a Kubernetes StatefulSet with persistent storage using PVC/EBS. Each service uses its own database schema such as auth_db, product_db, inventory_db, order_db, and payment_db. Redis is used for cart storage and product caching.

The application is deployed on a kOps Kubernetes cluster using Deployments, Services, StatefulSet, ConfigMaps, Secrets, Ingress, resource limits, readiness probes, liveness probes, and optional HPA. Prometheus scrapes application metrics, and Grafana is used for dashboards and monitoring.

Interview Explanation
------------------------

In this project, I designed a real-time e-commerce microservices application called CloudCart. The user accesses the React frontend through an AWS Load Balancer and NGINX Ingress. The frontend calls backend APIs through an API Gateway, which routes traffic to different microservices. Each microservice is independently deployed and communicates with MySQL or Redis as required. The Order Service coordinates with Inventory, Payment, Shipping, and Notification services to complete the order flow. The entire platform runs on Kubernetes and is monitored using Prometheus and Grafana.

apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: cloudcart-services
  namespace: ecommerce
  labels:
    release: kube-prometheus-stack
spec:
  namespaceSelector:
    matchNames:
    - ecommerce
  selector:
    matchLabels:
      cloudcart-monitor: "true"
  endpoints:
  - port: http
    path: /metrics
    interval: 15s

---
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: cloudcart-alert-rules
  namespace: ecommerce
  labels:
    release: kube-prometheus-stack
spec:
  groups:
  - name: cloudcart.rules
    rules:
    - alert: CloudCartServiceDown
      expr: up{namespace="ecommerce"} == 0
      for: 1m
      labels:
        severity: critical
        namespace: ecommerce
      annotations:
        summary: "CloudCart service is down"
        description: "A CloudCart target is down for more than 1 minute."

    - alert: CloudCartHighApiGateway5xx
      expr: sum(rate(api_gateway_http_requests_total{status=~"5.."}[2m])) > 1
      for: 1m
      labels:
        severity: warning
        namespace: ecommerce
      annotations:
        summary: "High 5xx errors in API Gateway"
        description: "API Gateway is returning high 5xx errors."

    - alert: CloudCartPaymentFailures
      expr: increase(payment_service_failed_total[5m]) > 3
      for: 1m
      labels:
        severity: warning
        namespace: ecommerce
      annotations:
        summary: "Payment failures detected"
        description: "Payment Service has multiple failed payments in the last 5 minutes."

    - alert: CloudCartPodRestarts
      expr: increase(kube_pod_container_status_restarts_total{namespace="ecommerce"}[10m]) > 2
      for: 1m
      labels:
        severity: warning
        namespace: ecommerce
      annotations:
        summary: "CloudCart pod restart detected"
        description: "A CloudCart pod restarted more than 2 times in the last 10 minutes."

    - alert: CloudCartHighMemoryUsage
      expr: |
        sum by (pod) (
          container_memory_working_set_bytes{namespace="ecommerce",container!="",image!=""}

      for: 2m
      labels:
        severity: warning
        namespace: ecommerce
      annotations:
        summary: "High memory usage in CloudCart pod"
        description: "A CloudCart pod is using more than 400 MB memory."

    - alert: CloudCartHighCPUUsage
      expr: |
        sum by (pod) (
          rate(container_cpu_usage_seconds_total{namespace="ecommerce",container!="",image!=""}[5m])

      for: 2m
      labels:
        severity: warning
        namespace: ecommerce
      annotations:
        summary: "High CPU usage in CloudCart pod"

18. Troubleshooting
--------------------

Problem: Pods stuck in ImagePullBackOff

Check image name:

kubectl describe pod <pod-name> -n ecommerce

Make sure your image exists:

docker pull $DOCKER_USER/cloudcart-product-service:v1

If your Kubernetes YAML still has placeholder:

grep -R DOCKER_USER_PLACEHOLDER k8s/

Fix:

sed -i "s|DOCKER_USER_PLACEHOLDER|$DOCKER_USER|g" k8s/backend.yaml
sed -i "s|DOCKER_USER_PLACEHOLDER|$DOCKER_USER|g" k8s/frontend.yaml

kubectl apply -f k8s/backend.yaml
kubectl apply -f k8s/frontend.yaml
Problem: MySQL pod running but tables missing

MySQL init scripts run only on first initialization. If PVC already exists, the init script will not run again.

For a full reset:

kubectl delete statefulset mysql -n ecommerce

kubectl delete pvc mysql-data-mysql-0 -n ecommerce

kubectl apply -f k8s/mysql.yaml
Problem: Frontend opens but APIs fail

Check API Gateway:

kubectl logs -n ecommerce deploy/api-gateway

Check Ingress:

kubectl describe ingress cloudcart-ingress -n ecommerce

Check direct API Gateway:

kubectl port-forward svc/api-gateway -n ecommerce 8081:80

Then:

curl http://localhost:8081/api/products
Problem: Prometheus does not show CloudCart metrics

Check ServiceMonitor:

kubectl get servicemonitor -n ecommerce

kubectl describe servicemonitor cloudcart-services -n ecommerce

Check service labels:

kubectl get svc -n ecommerce --show-labels

You should see:

cloudcart-monitor=true

Check metrics manually:

kubectl port-forward svc/product-service -n ecommerce 8082:80

curl http://localhost:8082/metrics
19. How to Explain This Project in Interviews

Use this explanation:

I built a production-style e-commerce microservices platform on Kubernetes. The architecture includes a React frontend, an API Gateway, and multiple Node.js backend services such as Auth, Product, Inventory, Cart, Order, Payment, Shipping, Notification, and Review services. MySQL is deployed as a StatefulSet with separate databases per service, and Redis is used for cart storage and product caching. Each backend service exposes health, readiness, and Prometheus metrics endpoints. The platform is deployed using Kubernetes Deployments, Services, Secrets, ConfigMaps, Ingress, resource limits, probes, and HPAs. Prometheus scrapes service metrics using ServiceMonitor, Grafana visualizes the platform, and PrometheusRule alerts detect service failures and payment issues.
